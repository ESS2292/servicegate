What it checks

  • servicegate check — primary command
  • Major-version drift across Docker Compose files, GitHub Actions jobs.<id>.services, Dockerfiles, Testcontainers string literals, and committed .env.example version variables
  • postgres:16 and postgres:16.14-alpine agree; postgres:15 vs postgres:16 does not
  • Minor or patch disagreement, when both pins spell out a minor, is a warning
  • A dev / local / override Compose file that pins a different major is a warning, not a failure (persistent local volumes are a documented reason to keep an older major)
  • Unpinned tags (:latest or a missing tag) are warnings, or errors with --strict-pins
  • A GitHub Actions service for a known family with no --health-cmd is a warning
  • A single-version core pin that is not in a CI version matrix is a warning
  • --json, --ignore, --root, --strict-pins, --include-fixtures
  • Exit codes: 0 pass, 1 violations, 2 usage or missing root

What it is not

  • Not a Dockerfile style linter (see hadolint) and not a digest pin writer
  • Not a full YAML 1.2 parser (no anchors or merge keys)
  • Does not resolve Testcontainers library defaults or dynamically built tags
  • Does not call the network, look up Docker Hub, or check an end-of-support calendar
  • Language runtime images (node, python, golang, …) are out of scope — use RuntimeGate
  • Lite (the GitHub Action) does not read Dockerfiles, Testcontainers, or .env.example

CI sketch

From the bundled workflow sketch. The paid CLI is not published to npm; unpack the tarball and point the job at the binary, or install it from the unpacked tree.

.github/workflows/servicegate-example.yml 
# Example only — copy into a consuming repository. The paid CLI is not published yet.
name: ServiceGate

on:
  pull_request:
  push:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Run ServiceGate
        run: node /path/to/servicegate/bin/servicegate.js check

Honest limits

  • Workflow and Compose parsing is best-effort, not a full YAML 1.2 implementation. Anchors, merge keys, and some generated expressions can be missed.
  • Testcontainers detection looks for string literals that already look like postgres:16-alpine, and only in files that import a Testcontainers library. It does not resolve library defaults, constructor helpers, or dynamically built tags.
  • Image families are a fixed list: Postgres (including Bitnami, pgvector, PostGIS, Timescale, and Supabase images), Redis, Valkey, MySQL, MariaDB, MongoDB, Elasticsearch, OpenSearch, RabbitMQ, Kafka (including Redpanda), Memcached, MinIO, LocalStack, ClickHouse, Cassandra, Neo4j, InfluxDB, and CockroachDB. An unusual fork or a renamed image is skipped rather than guessed at.
  • Major-version comparison is the contract. Patch freshness against Docker Hub, digest pinning, and end-of-support calendars are out of scope for 0.1.0 and are not looked up on the network.
  • A GitHub Actions matrix is expanded from strategy.matrix (including include rows). Dynamic matrix generation is not resolved.
  • .env files that are gitignored are not read; only committed example env files supply variable values. Lite does not read those files at all, but still honors Compose ${VAR:-default} defaults.

FAQ

Is this the same as RuntimeGate?

No. RuntimeGate checks whether language runtime version pins (Node.js, Python, Go, and so on) agree. ServiceGate checks whether data-store and sidecar image pins (Postgres, Redis, and related families) agree. They share an audience (CI and DevOps) and the same “fail the job, not the deploy” idea. The free RuntimeGate Lite, EnvGate Lite, and LockGate Lite Actions are published separately.

Why $19 if the source is MIT?

MIT allows selling copies. The price is for a packaged, tested release with docs and a CI sketch, not exclusive ownership of the code. Buyers (and others) may redistribute under MIT terms.

What about a dev Compose file that stays on an older Postgres major?

That is treated as a warning, not a failure. A documented case is NangoHQ/nango #6287, where the author did not want the persistent local volume moved off Postgres 15 even after the public compose file moved to 16. ServiceGate classifies dev / local / override Compose files that way on purpose.

Does Lite check Dockerfiles or Testcontainers?

No. ServiceGate Lite compares Docker Compose files to GitHub Actions services: only. Dockerfiles, Testcontainers literals, and .env.example interpolation are in the full CLI. Checkout is not live.
