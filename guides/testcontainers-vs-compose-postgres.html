When Testcontainers and Compose pin different Postgres majors

Tests that start their own container can keep an older image after the public Compose file moves on. The disagreement is often invisible until a query or a dump fails.

NangoHQ/nango #6287 (opened 28 May 2026) reports that the public self-host Compose file pinned postgres:16.0-alpine while the Testcontainers setup in tests/setup.ts still used postgres:15.5-alpine. The issue asked for the ephemeral test database to match the public self-host Postgres major. It deliberately did not want dev/docker-compose.dev.yaml moved off Postgres 15, because that file uses a persistent bind-mounted volume.

Follow-up pull request #6426 (“Move versions to a single source-of-truth”) tried to put Postgres and Redis versions in .env.example and was closed stale on 9 August 2026 without merging. A scan of NangoHQ/nango at 316378b8c91f045f6a49b32ff90ed13885b509b3 (10 November 2026, 12:10 PM America/New_York) still reported the Postgres 16 vs 15.5 disagreement, plus a Redis 7.2.4 (Compose) vs 8.0.4 (Testcontainers) disagreement that the ticket did not mention. The dev Compose file still pinned postgres:15.5-alpine; because that file is a dev/override role, it is a warning-class source rather than an error. That matches the issue author’s note that the persistent local volume should not be forced onto 16. This write-up does not claim the project uses ServiceGate.

Treat test pins as first-class, and leave intentional local drift as a warning

A practical pattern is: when you bump the public or CI Postgres (or Redis) major, bump the Testcontainers image in the same change, or point both at a committed example env variable. Keep a persistent local volume on an older major if you have to — but make that difference visible, not silent.

The free ServiceGate Lite Action compares Compose files to GitHub Actions services: only, so it would not have seen the Testcontainers pin in nango #6287. The full CLI also reads Testcontainers string literals (in files that import a Testcontainers library) and committed .env.example version variables, and it reports dev/override Compose drift as a warning.
